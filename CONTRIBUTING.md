# Contributing

Thank you for helping. This is a small project with one maintainer, so please open an issue before a large change.

## Ground rules

- **Synthetic data only.** Never commit a real E-Redes file, a real CPE code or any household's consumption, not even "anonymised". Test files live in `fixtures/synthetic/` and are generated by `npm run fixtures` from `web/src/testing/synthetic-fixtures.ts`. Any other `.xlsx` or `.xls` file is ignored by Git on purpose. If you need a new case (a new layout, a clock-change day, a malformed file), add it to the generator and describe it in `fixtures/synthetic/README.md`.
- **Consumption data never leaves the device.** Do not add analytics, remote fonts, CDNs or any request to another origin. The privacy test (`web/e2e/privacy.spec.ts`) and the Content Security Policy in `web/src/index.html` must keep passing unchanged.
- **The ranking is ordered by cost only.** No sponsored placement, no affiliate links.
- **No secrets.** The project needs no accounts, API keys or tokens. Do not add any.
- **Language.** Code, identifiers, comments and log messages in English. UI text in European Portuguese.
- **No em-dashes** in the READMEs, `docs/*.md`, the catalogue or the UI text. Use a comma, a colon or a full stop. `node scripts/check-docs.mjs` enforces this.

## Updating the tariff catalogue

The catalogue is versioned YAML in `catalogue/`. The browser never parses YAML: `npm run catalogue:build` validates it and writes `web/public/data/catalogue.json`, which is committed.

1. Use only public sources: a supplier tariff page, its standard information sheet (FIN), ERSE publications or ERSE open data. No values from private quotes, screenshots of logged-in pages or forum posts.
2. Every offer, tariff and tax needs a `source_url` pointing to the page or document where the value is published, and a `verified_on` date (`"YYYY-MM-DD"`) of the day you checked it. When you change a value, update both.
3. Never guess a missing number. Leave it `null` (or list the component under `unpriced_components`), add an entry to `catalogue/UNVERIFIED.md` with the next free id, and reference that id in the entry's `unverified` list. The app shows these gaps as assumptions.
4. Indexed formulas are structured parameters (for example `k_eur_mwh`, `loss_factor`), not expressions. If an offer needs a formula shape the engine does not support, open an issue first.
5. Prices exclude VAT (`prices_include_vat: false`). VAT and fees belong in `taxes.yaml`.
6. Bump `catalogue_version` in `catalogue/catalogue.yaml` to the date of the latest verification (`YYYY.MM.DD`). Bump `schema_version` only when the structure changes.
7. Run `npm run catalogue:build`, then `npm run catalogue:check` and `npm test` from `web/`, and commit the YAML and `web/public/data/catalogue.json` together.

## OMIE prices

`web/public/data/omie/` is updated by the daily workflow `.github/workflows/omie-prices.yml`. Do not edit these files by hand. To refresh them locally, run the `fetch` and `verify` commands from [jobs/omie-prices/README.md](jobs/omie-prices/README.md).

## Development

Local development is Windows-native (PowerShell, no Docker, no WSL). You need Node.js 22.18 or later, and the .NET 10 SDK for the OMIE job.

From `web/`:

| Command | What it does |
| --- | --- |
| `npm ci` | Install dependencies |
| `npm start` | Dev server on http://localhost:4500 |
| `npm test` | Type checks, script tests and unit tests |
| `npm run build` | Production build |
| `npm run e2e` | Playwright behaviour and privacy tests on port 4510 (run `npx playwright install chromium` once first) |
| `npm run evidence` | Regenerate the screenshots in `docs/evidence/` |
| `npm run catalogue:check` | Validate the catalogue and check that `catalogue.json` is up to date |
| `npm run catalogue:build` | Regenerate `catalogue.json` |
| `npm run fixtures` | Regenerate the synthetic files |

From the repository root:

| Command | What it does |
| --- | --- |
| `dotnet test jobs/omie-prices/OmiePrices.slnx` | OMIE job tests |
| `node scripts/check-docs.mjs` | Document checks (`--self-test` tests the checker itself) |

## Before you open a pull request

- `npm run catalogue:check`, `npm test`, `npm run build` and `npm run e2e` pass in `web/`.
- `dotnet test jobs/omie-prices/OmiePrices.slnx` passes if you touched the job.
- `node scripts/check-docs.mjs` passes.
- If you changed a screen, regenerate the screenshots with `npm run evidence` and look at them at both widths.
- If you changed the cost engine, the hand check in `docs/HAND-CHECK.md` and `web/src/app/engine/hand-check.spec.ts` must still agree within 1 %.

CI runs the same checks on every push and pull request.
